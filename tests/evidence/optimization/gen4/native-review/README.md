No `lean_nat_pow`, `lean_nat_div` or `lean_nat_mod` occurs in that branch. The `payloadWordBits` helper is inlined into this function; its out-of-line definition exists in the object but is absent from the linked CLI. The new bound theorems have no emitted C functions or calls.

The linked [payloadBits assembly](binary-payloadBits.asm) confirms the branch structure. At `0xb4e5c2`, the scalar width is compared against Lean's tagged value `0x81` for 64; wide widths branch to `0xb4e6cb`. The narrow path contains machine `shr %cl,%r14` at `0xb4e5ec`, `shl %cl,%rax` at `0xb4e63a`, `not %rax` at `0xb4e63d`, and `and %rax,%r14` at `0xb4e640`. The mask uses an equivalent complement-of-shifted-all-ones form. The result is converted to a tagged Nat by `lea 0x1(,%r14,2),%rax` at `0xb4e643`. Big natural inputs retain a conversion through the standard Lean runtime. Nat index arithmetic and reference-count handling remain; no allocation or throughput claim is inferred from this inspection.

The width-at-least-64 fallback is retained with the original unrestricted natural-number arithmetic. C lines 95–100 contain exactly two powers, one division and one remainder. Native calls to `lean_nat_pow` remain at `0xb4e6d3` and `0xb4e74d`, with scalar division instructions and the big-natural division/remainder calls confined to the wide branch. This statement is about the body of `payloadBits`: other functions in the same module, such as signed payload interpretation, still use powers independently.
