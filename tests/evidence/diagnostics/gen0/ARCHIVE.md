# Generation 0 diagnostic evidence

These are untimed instruction/allocation diagnostics of the unchanged generation 0 decoder. They are not new throughput results. The accepted throughput baseline is recorded separately in `bench/BASELINE.md`.

`archive-manifest.json` maps each retained file to its original cache/generated-code path, byte count and SHA-256. Raw Callgrind dumps use deterministic gzip (mtime zero, no filename); both compressed and uncompressed hashes are recorded. To inspect a raw dump, run `gzip -dc callgrind-v3/MODE/callgrind.out.1.gz`. Original files remain under `.cache/gen1-planning/`.

- `driver-v1/`, `driver-v2/`, `driver-v3/` retain diagnostic source, generated C, build commands and validation snapshots. Executable/object/large symbol files remain in cache and are identified by SHA-256 in the manifest. Every diagnostic executable links the unchanged production objects; build manifests record their hashes.
- `generated-c/` preserves all 20 reused production/model C modules before any optimization rebuild. Its `Impl/Parity.c`, `Impl/Bits.c`, `Impl/Message.c`, `Impl/CommB.c` and `Impl/Semantics.c` support source-line inspection of the live path.
- `driver-all-census.jsonl` retains complete-corpus counts, full-model Repr digest and post-loop candidate-set census. `driver-v2/validation.json` checks all five candidate and all five score probes against that census.
- `probe-campaign.json` records all ten passing supplemental profiles. Candidate/core-eligibility costs include hard checks and conditional scores; score-only probes include only reached scores. These overlap each other and whole-message work and must not be added to those totals. BDS44/45 have no reached score population in this corpus.
- `callgrind-v3/MODE/` contains each completed controlled run's exact command, copied controller source, control acknowledgements and explicit instrumentation-state output, counts/digest, logs and raw dumps. The primary profile is **callgrind.out.1.gz**, dumped before instrumentation is disabled. The final termination dump can have zero totals and a wrapped summary; it is preserved as a tooling artifact and is not used as decoder cost.
- `callgrind-controls-smoke*` retains early controller timeout/ptrace attempts and the successful nonempty no-ptrace smoke. Those early issues are diagnostic tooling failures/warnings, not decoder or differential failures. The final controller uses normal no-op poll wakeups with `vgdb --max-invoke-ms=0`.
- `callgraph-review.md` records actual compiled sharing/repetition and attribution limits. `profile-options.md` and `profiling-tools/` retain profiler availability, package hashes and wrappers.

The archive script is retained as `archive_diagnostics.py`; its executed command was `python3 .cache/gen1-planning/archive_diagnostics.py`. It verifies every reused production object's hash, preserves prior retained bytes and skips still-running profiles. `incomplete_profiles` in the manifest explicitly records any skipped run. It can be rerun after that run completes, before production objects are rebuilt. The analysis agent maintains the neighboring `native-df`, `parser`, `perf` and `callgrind` analysis directories; their files are outside this raw-archive manifest's membership.
