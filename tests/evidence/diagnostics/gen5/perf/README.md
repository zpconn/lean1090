# Gen5 native sampling evidence

This is one native `perf record -e cpu-clock:u -F 199 --call-graph dwarf,16384` pass over the complete corpus through the frozen headline worker, pinned to guest logical CPU 0. It is diagnostic sampling, not an ABAB benchmark or a throughput measurement. The worker's raw response is retained only to show protocol completion; do not use its instrumented duration as a performance result.

The capture runs the actual gen5 timed binary, SHA-256 `6d1576d363d6fa03fea5a9ac55aaa26a323ee5011c8ad38df99821fa58a7e4ab`, from commit `eeb58261e6be0c2b87385f3064a88aed00d4d19a`. The helper verifies all 22 linked source/C/object/trace sets against `bench/runs/gen5/fresh-native-inputs.json`, every source against its committed blob, and all native hashes against `binary-built.json`. All 96 captured input hashes match before and after. The diagnostic driver build finished before this pass; native diagnostic and Callgrind jobs were held until capture completion. Other agents could read evidence or prepare orchestration. This does not establish Windows host-wide isolation.

`run_perf_gen5.py` and `analyze_perf_gen5.py` adapt the retained gen4 helpers. The capture command, inputs, affinity, preserved binary path and raw-data hash are in `capture.json`. The preserved binary copy is for later symbol lookup and was not executed. Raw perf data remains `.cache/gen6-planning/perf-gen5/perf.data`; the campaign archiver retains it via its explicit `--perf-data` option. The helper does not rebuild any production code or alter the native image.

All 420 recorded samples parse. Both `report-self.txt` and `report-children.txt` explicitly report `# Total Lost Samples: 0` at line 4. Exactly 259 samples have the live `Impl.decode` frame; 161 others are excluded and separately classified. Unknown frames occur in 416 recorded stacks and 28 included leaf positions. Missing, inlined or tail-called frames may bias the visible subset; absence of the decoder frame does not prove a sample is preparation. The unresolved report substage remains explicit. The disjoint tables sum to 259; nested Rat/GMP/Parity/software-binary64/enclosure categories overlap and must not be added together. No density-table lookup frame was observed in the included subset; that does not establish zero lookup cost.

The runtime eagerly initializes its 13 immutable field-density tables and the new 1,024-entry Mach-value table during module startup before `main`. These initialization costs are outside the decode-visible subset when their actual stacks lack `Impl.decode`; they are not silently assigned to a decoder stage. The recording also contains input preparation, result consumption/destruction, runtime startup and possible unwind failures. Conditional shares among the 259 visible decoder stacks are not whole-decoder timing shares or proof of causal speedup. The full benchmark and the exhaustive Callgrind cost accounting are separate evidence.
