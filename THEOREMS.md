# Theorem contracts

The statements below are named `Prop` contracts in `Capstones.lean`. All 23 contracts have completed proofs, including complete runtime refinement, wire round-trips, all parity and altitude contracts, CPR accuracy/latitude zones/tracking and Comm-B inference/arithmetic. The full gate checks the exact final manifest; PROGRESS.md records the executed validation. The file contains no placeholder proofs. This makes the requested freeze workable: after approval, separate `Proofs/` modules must prove these exact propositions, with refinement instantiated by the actual implementation. A proposition definition having no axioms is not evidence that the proposition is true. `scripts/Final.lean` fixes every exact theorem type, binding refinement to `Lean1090.Impl.decode`, prefix refinement to `Impl.decodePrefix`, CPR tracking to `Impl.decodePositions`, and the pilot to `Impl.BDS50.decode`. The manifest is an import-free declaration fragment. The frozen checker prepends integration imports in a temporary module and compiles the exact unchanged manifest bytes, then checks its actual proving constants with `#print axioms`. Thus the frozen reference sources do not import Impl or Proofs, while the final theorem types still name the real implementation. It fails if any required implementation or proof is missing or has the wrong type.

The concrete non-vacuity lemmas cited below **are proved now**, using the Lean kernel. `scripts/AuditWitnesses.lean` audits those actual proof constants. They establish inhabited hypotheses and selected examples, not the universal capstones. The only permitted axioms in capstone proofs are `propext`, `Classical.choice` and `Quot.sound`; fewer are fine.

`Spec.decode` returns exact field assignments plus deterministic semantic reports. `Spec.encode` independently places fields in transmission order. The encoder never calls the decoder or searches for a preimage. The report includes the proof-visible exact semantic payload, strings, unavailable values and ordered Float-expression operands from `Spec/Semantics.lean`; refinement therefore covers those derived meanings as well as raw codes. Rounded JSON is a presentation projection and is not claimed invertible. Frame and payload encoders retain every raw field code, including ignored/reserved bits; those bits do not acquire new aircraft meanings.

The headline benchmark times exactly the function in the final refinement theorem: `Impl.decode`, including any total projection from a native representation into the complete proof model. It retains that complete result. Native-only time may be reported separately, but cannot establish the speed target. The projection must translate every actual reported field and cannot call reference decoders or substitute freshly recomputed reference answers. `Model/` contains shared data types only; `Impl/` cannot import `Spec/` or Mathlib directly or transitively. `scripts/check_impl_imports.py` checks the compiled module graph, including four rejection self-tests. It also checks all frozen Lean import headers and the complete reference module graph: only Spec, Model, Mathlib and Lean standard libraries are allowed, with no transitive Impl or Proofs dependency. `Model.BDS50.Result` is defined in Model/BDS50.lean. Model types, the final manifest, lock checker, inventory and audit scripts are in the frozen inventory. Float presentation retains its separately stated tested boundary.

## Refinement

Every byte input produces the reference result, including failures and every exact decoded field. This prevents optimization from changing parsing, parity acceptance, semantic values or candidate inference.

```lean
def Refinement (implementation : List UInt8 → Option Message) : Prop :=
  ∀ bytes, implementation bytes = Spec.decode bytes
```

No input hypothesis. `Spec.refinement_nonvacuous` proves a successful nonempty DF11 example. The implementation parameter is intentional: section 4 must instantiate it with `Impl.decode`, never with `Spec.decode` to claim success.

## BDS50Refinement

The full BDS50 runtime path equals the reference for every input, including all hard checks, binary64 density and penalty operations, the inclusive score gate, and the complete returned fields. This prevents treating a Float-dependent acceptance branch as an unproved presentation detail.

```lean
def BDS50Refinement (implementation : Nat → Option Model.BDS50.Result) : Prop :=
  ∀ word, implementation word = Spec.bds50Reference word
```

No hypothesis restricts the input. This capstone is already proved by `Proofs.BDS50.refinement` and bound to `Impl.BDS50.decode` in scripts/Final.lean. `Proofs.BDS50.pilot_nonvacuous` proves an accepted complete result exists; `exact_threshold_nonvacuous` proves an attainable score exactly −3 and adjacent pass/fail cases. The source is explicitly rs1090-derived. The exact function and complete output are timed; docs/BDS50-PILOT.md records the corpus and structured differential checks and the slower measured baseline.

## PrefixRefinement

The streaming entrypoint consumes exactly one DF-sized message and preserves the unused suffix. This prevents confusing `Message::from_bytes` with its stricter whole-slice conversion.

```lean
def PrefixRefinement
    (implementation : List UInt8 → Option (Message × List UInt8)) : Prop :=
  ∀ bytes, implementation bytes = Spec.decodePrefix bytes
```

No input hypothesis. `Spec.prefix_nonvacuous` proves a seven-byte message followed by an untouched byte 0xAA.

## MessageRoundTrips

Every valid independently assigned message encodes and decodes identically. Every accepted byte message is reconstructed bit for bit, including retained reserved bits, which is stronger than preserving only defined bits.

```lean
def MessageRoundTrips : Prop :=
  (∀ fields, Valid fields →
    Spec.decode (encodeFrame fields) = some (assigned fields)) ∧
  (∀ bytes f, Spec.decode bytes = some f → Spec.encode f = bytes)
```

`Valid : Frame → Prop` requires only independent wire-field receiver predicates. BitVec enforces field bounds. Semantic report construction is in the theorem conclusion (`assigned fields`), never in a validity hypothesis; both that hypothesis and the complete `assigned` conclusion constructor are audited for decoder/helper dependencies. `assigned` now uses independent MSB-first field assembly and Gray-prefix altitude arithmetic in Spec/Assignment*.lean, rather than calling `report`. The all-input equality to the decoder is proved in `Proofs/MessageRoundTrips.lean`. Receiver validity excludes bad DF17 parity and declared payload heuristics such as AC12>50000 ft. Raw field round-trips and altitude representability are not restricted by that heuristic. `Spec.roundTrips_nonvacuous` proves accepted examples for all eleven format families; Comm-D follows the standard despite the oracle over-read.

## ADSBRoundTrips

Every TC, subtype and version field assignment in the declared schema round-trips. Every successful ADS-B payload decode reproduces its 56 bits. This detects wrong offsets, layout selection, dropped status bits and lossy encoders.

```lean
def ADSBRoundTrips : Prop :=
  (∀ f, ValidADSB f → decodeADSB (encodeADSB f) = .ok f) ∧
  (∀ word f, decodeADSB word = .ok f → encodeADSB f = word)
```

`ValidADSB` requires named fields in schema order, each code within its bit width, matching discriminants, and the explicit altitude/reserved-bit receiver checks. These fail on malformed assignments, not on ordinary quantization uncertainty. `Spec.adsb_nonvacuous` proves examples for all 32 TCs, every decoded subtype and each operational-status version. Rounded callsigns, speeds and altitudes alone are not the field-assignment domain.

## FrameRoundTrips

Every structural frame field assignment round-trips, without narrowing the domain to what the oracle receiver currently accepts. Successful structural parses reconstruct every bit. This prevents a receiver heuristic from making the standard field theorem vacuous.

```lean
def FrameRoundTrips : Prop :=
  (∀ f, decodeFrame (encodeFrame f) = some f) ∧
  (∀ bytes f, decodeFrame bytes = some f → encodeFrame f = bytes)
```

Frame fields are bounded by BitVec types; there is no receiver-acceptance hypothesis. Even DF17 bad parity remains representable as a wire assignment. `Spec.commD_witness` is a concrete structural decode, and `roundTrips_nonvacuous` covers the eleven format families. Semantic validity and acceptance belong to the separate MessageRoundTrips proposition.

## ADSBFieldRoundTrips

Every representable ADS-B schema assignment round-trips through the unfiltered field codec, covering the full bit domains of every type code, subtype and version.

```lean
def ADSBFieldRoundTrips : Prop :=
  (∀ f, ValidADSBFields f → decodeADSBFields (encodeADSB f) = .ok f) ∧
  (∀ word f, decodeADSBFields word = .ok f → encodeADSB f = word)
```

`ValidADSBFields` requires only field names/order/width and consistent layout discriminants. It does not assume the oracle 50000 ft ceiling or reserved-bit receiver filters. `Spec.adsb_full_fields_nonvacuous` proves that a 50175 ft assignment is in this full domain and decoded by the field codec while the receiver rejects it. The separate ADSBRoundTrips statement preserves the receiver-facing guarantee too.

## CRCPolynomial

The shift-register CRC is the remainder of polynomial division over GF(2) by the independently listed generator powers. This prevents a self-consistent encoder/decoder from agreeing on the wrong CRC polynomial or bit order.

```lean
def CRCPolynomial : Prop :=
  ∀ width word,
    Parity.polynomial 24 (Parity.syndrome width word).toNat =
      Parity.polynomialRemainder width word
```

No input hypothesis: high bits above the chosen width are ignored by both definitions. `Spec.crc_polynomial_nonvacuous` provides a nonempty published 112-bit frame with zero syndrome. That witness does not prove the general polynomial identity.

## CRCLinear

CRC is linear under XOR for every word width. This detects incorrect initial states, complements, and nonlinear bit operations.

```lean
def CRCLinear : Prop :=
  ∀ width a b,
    Parity.syndrome width (a ^^^ b) =
      Parity.syndrome width a ^^^ Parity.syndrome width b
```

No input hypothesis. `Spec.crc_linear_nonvacuous` checks two nonzero 56-bit operands and their XOR.

## CRCSingleBit

At both permitted frame lengths, every single-bit error is detectable and has a syndrome distinct from every other single-bit error in that frame. This supports unique single-error localization without claiming general error correction.

```lean
def CRCSingleBit : Prop :=
  ∀ width, width = 56 ∨ width = 112 →
    (∀ i : Fin width, Parity.syndrome width (2^i.val) ≠ 0) ∧
    (∀ i j : Fin width,
      Parity.syndrome width (2^i.val) = Parity.syndrome width (2^j.val) → i = j)
```

Width must be 56 or 112; a Fin index guarantees the error bit is inside that frame. Distinctness is within each width, not between different widths. `Spec.crc_singleBit_nonvacuous` proves distinct nonzero syndromes for first/last bits at both widths.

## ParityOverlay

Appending the encoded parity XOR an address/interrogator overlay recovers exactly that overlay at the receiver. This detects AP/PI alignment and XOR mistakes.

```lean
def ParityOverlay : Prop :=
  ∀ width, width = 32 ∨ width = 88 → ∀ information,
    information < 2^width → ∀ address : BitVec 24,
    Parity.syndrome (width+24)
      (information*2^24 + (Parity.overlay width information address).toNat) = address
```

The information width is 32 or 88 and the information fits that width. Otherwise the word would not be a legal short/long field assignment. No authenticity or corruption-free premise is smuggled into the algebra. `Spec.parity_overlay_nonvacuous` uses a nonzero DF11 overlay 0x55.

## AltitudeRoundTrips

Every representable 25-foot and 100-foot Gillham altitude round-trips through both AC13 and AC12. This detects Gray-code reflection, bit interleaving, offset and M/Q-bit errors.

```lean
def AltitudeRoundTrips : Prop :=
  (∀ h, Altitude.Representable25 h →
    (∃ w, Altitude.encode25AC13 h = some w ∧
      Altitude.decodeAC13 w = some (.feet h)) ∧
    (∃ w, Altitude.encodeFeetAC12 .binary25 h = some w ∧
      Altitude.decodeAC12 w = some h)) ∧
  (∀ h, Altitude.RepresentableGillham h →
    (∃ w, Altitude.encodeGillham h = some w ∧ Altitude.decodeGillham w = some h) ∧
    (∃ w, Altitude.encodeFeetAC12 .gillham100 h = some w ∧
      Altitude.decodeAC12 w = some h))
```

The 25-foot domain is −1000..50175 ft in 25 ft steps; Gillham is −1200..126700 ft in 100 ft steps. Values outside these domains have no exact code of the chosen type. The theorem includes heights above the oracle 50000 ft heuristic. `Spec.Altitude.binary25_nonvacuous` and `gillham_nonvacuous` prove 38000 ft in both field widths. Metric and GNSS helpers remain explicitly separate source/version choices, not silently included in a feet theorem.

## AltitudeRejection

Invalid Gillham patterns are rejected, and unrepresentable feet assignments have no encoding. This prevents a malformed Gray code or rounded altitude from being reported as valid.

```lean
def AltitudeRejection : Prop :=
  (∀ w, Altitude.validGillham w = false → Altitude.decodeGillham w = none) ∧
  (∀ h, ¬ Altitude.Representable25 h → Altitude.encode25AC13 h = none) ∧
  (∀ h, ¬ Altitude.RepresentableGillham h → Altitude.encodeGillham h = none)
```

Each implication assumes precisely the independently defined invalidity predicate. Invalid C counts are 0, 5, 6; M/Q and field-width constraints are explicit. `Spec.Altitude.invalid_gillham_nonvacuous` uses raw code 2; `Spec.altitude_rejection_nonvacuous` uses 1 ft outside both step domains.

## CPRLocal

Local airborne and local surface decoding recover the encoded position within half a quantization step, for each parity. The encoder rounds latitude before selecting its longitude grid, as ICAO specifies.

```lean
def CPRLocal : Prop :=
  ∀ (mode : CPR.Medium) (odd : Bool) (p reference : CPR.Position),
    CPR.LocalAdmissible mode odd p reference →
    ∃ q, CPR.decodeLocal mode (CPR.encode mode odd p) reference = some q ∧
      CPR.WithinResolution mode odd p q
```

`LocalAdmissible` requires valid physical/reference coordinate ranges and strict half-cell proximity to the **quantized** latitude and longitude. Longitude distance is circular. A physical half-cell bound without the rounding margin can fail only in a half-step strip at its boundary; the exact latitude strip is <0.000024° airborne and <0.000006° surface, proved by `local_latitude_rounding_band`. `local_margin_needed` proves an actual alias 6° away despite physical distance <3°. There is no extra assumption that the true and rounded latitude have equal NL. `CPR.local_nonvacuous` proves every medium/parity at 0°, 0°. The general half-step error bound is proved in Proofs/CPRGeometry.lean.

## CPRGlobal

An airborne even/odd pair with unambiguous separation and encoder-side quantized-zone compatibility recovers the selected report to half-step precision. Both recency choices and a moving aircraft are covered.

```lean
def CPRGlobal : Prop :=
  ∀ (pEven pOdd : CPR.Position) (latestOdd : Bool),
    CPR.GlobalAdmissible pEven pOdd →
    ∃ q, CPR.decodeGlobal (CPR.encode .airborne false pEven)
      (CPR.encode .airborne true pOdd) latestOdd = some q ∧
      CPR.WithinResolution .airborne latestOdd (if latestOdd then pOdd else pEven) q
```

`GlobalAdmissible` requires valid coordinates, quantized latitude separation <3/59°, equal NL values on the two **encoder-side rounded latitudes** (`roundedLatitude .airborne false pEven.lat` and its odd counterpart), and circular quantized longitude separation <180/(NL*(NL − 1))° (unrestricted at NL1). These bounds determine the unique integer zone index. No admissibility hypothesis calls `decodeGlobal` or `globalLatitudes`: reconstructing those quantized latitudes is part of what must be proved. The zone condition can fail at a transition even for close physical positions; unlike a physical-zone restriction it tests the actual two quantized values. The 30 s oracle pairing window alone cannot guarantee these physical conditions. `three_nm_latitude_margin` proves that 3 NM latitude displacement plus worst half-step errors remains below 3/59°. Concrete counterexamples `global_latitude_separation_needed` and `global_longitude_separation_needed` show that dropping either separation bound aliases by an entire zone even when the NL check passes. `global_nonvacuous` and `global_witness_moves` prove a nonstationary pair. No global surface claim is made.

## CPRZoneRejection

A pair whose reconstructed latitudes occupy different NL zones is rejected. This detects a missing or misordered zone check.

```lean
def CPRZoneRejection : Prop :=
  ∀ even odd latestOdd, ¬ CPR.SameDecodedZone even odd →
    CPR.decodeGlobal even odd latestOdd = none
```

The condition is on `globalLatitudes`, never on unknowable physical positions. Opposite physical zones can quantize into one decoded zone within a rounding step of a transition; the source encoder uses each rounded latitude. `zone_rejection_nonvacuous` supplies bounded, correctly paritied coordinates on opposite reconstructed zones and `zone_rejection_witness` proves rejection for both recency orders. A physical-zone rejection theorem would be false.

## CPRLatitudeZones

All 57 rational transition certificates bound the Real.arccos formula and exclude every decodable latitude. The executable NL table therefore equals the real definition on every airborne/surface, even/odd reconstruction grid, including ±87°.

```lean
def CPRLatitudeZones : Prop :=
  (∀ c ∈ CPR.nlCertificates,
    CPR.CertifiesTransition c ∧ CPR.AvoidsDecodableLatitudes c) ∧
  (∀ lat, CPR.DecodableLatitude lat → CPR.nlTable lat = CPR.nlFormula (lat : ℝ))
```

`DecodableLatitude` is the union of the four legal latitude grids within [-90, 90]. Decimal thresholds are not claimed equal to irrational transitions at every real input. The finite grid-separation and analytic interval bounds are conclusions to prove, not assumptions. The candidate-generation script is numerical evidence only. `nl_certificate_nonvacuous` proves the certificate list is nonempty; `CPR.nl_nonvacuous` proves 0° is attained. `nl_formula_zero` is proved. `nl_87_discrepancy` proves 87° is attained and distinguishes standard NL2 from oracle NL1; that point is not excluded to make the theorem true.

## CommBInference

The reported register set is exactly the registers whose complete validity and score predicates pass, carrying the exact corresponding fields. No winner is substituted for an ambiguous set.

```lean
def CommBInference : Prop :=
  ∀ df altitude word register fields,
    (register, fields) ∈ inferCommB df altitude word ↔
      commBEligible df altitude register word = true ∧
      decodeBDS register word = some fields
```

This is explicitly **rs1090-derived**, as requested. It includes header/status checks, plausibility bounds, every binary64 score operation, all-zero MB, DF20/21 selection and the pinned BDS65 offset/length rejection. No extra valid-message hypothesis restricts the equality. `Spec.commBInference_nonvacuous` proves a real scored BDS40 survivor, including actual list membership. BDS65 has a direct codec witness but cannot honestly have an inference acceptance witness because the pinned selector always rejects it. See docs/COMMB.md.

## CommBRoundTrips

Each direct register codec round-trips all valid field assignments and exactly reconstructs accepted payloads. This includes all 14 register layouts even when inference would suppress one.

```lean
def CommBRoundTrips : Prop :=
  (∀ f, ValidBDS f → decodeBDS f.kind (encodeBDS f) = some f) ∧
  (∀ register word f, decodeBDS register word = some f → encodeBDS f = word)
```

`ValidBDS` requires explicit field-name/order/width constraints and the register’s wire/field validity predicate. It does not assume a round-trip result; it does not require the separate score gate. Its use of independent field placement to apply a wire predicate is not a search for an accepted preimage. `Spec.bds05_nonvacuous` through `bds65_nonvacuous` prove one concrete assignment for every register. rs1090-derived supplementary tables and filters are listed below.

## CommBFieldRoundTrips

Every structurally valid register assignment round-trips through its independent field codec, even outside the oracle inference plausibility envelope. This covers the full source field domains instead of obtaining an easy theorem by calling ordinary representable values invalid.

```lean
def CommBFieldRoundTrips : Prop :=
  (∀ f, ValidBDSFields f → decodeBDSFields f.kind (encodeBDS f) = some f) ∧
  (∀ register word f, decodeBDSFields register word = some f → encodeBDS f = word)
```

`ValidBDSFields` enforces supported layouts, named field width/order and necessary header/typecode/subtype/version discriminants. It does not apply the hard plausibility filters, score gates or per-message selection. `Spec.bdsFields_nonvacuous` proves a BDS50 assignment with 1000 kt groundspeed and 60 kt TAS round-trips structurally while the oracle rejects it; `bdsAllFields_nonvacuous` covers all 14 direct register layouts. ## CommBArithmetic

All operations used to decide candidate acceptance stay within the finite rational model of binary64, and every executed division has a nonzero denominator. This prevents treating overflow or division-by-zero behavior as harmless Float presentation.

```lean
def CommBArithmetic : Prop :=
  ∀ register, register ∈ commBCoreRegisters → ∀ word, word < 2^56 →
    CommBScoreArithmeticFinite register word
```

The register belongs to the 12 core candidates and the payload fits 56 bits; no plausibility/acceptance assumption narrows the input domain. `Spec.commB_arithmetic_domain_nonvacuous` proves these premises, and `commBArithmetic_nonvacuous` additionally proves a complete finite arithmetic trace for BDS40. Floating library behavior is cross-checked in section 4; exact proof-visible nearest-even rounding is specified in Binary64. The finite-domain theorem alone does not prove that an external compiler implements IEEE arithmetic correctly.

## CPRTrackingRefinement

The complete stream transition matches the pinned tracking policy: per-address state, pairing, references, time windows, ordering and every resolved or unresolved result. This prevents optimizing only the CPR equations while changing which reports are paired.

```lean
def CPRTrackingRefinement
    (implementation : CPR.Policy.Geography → CPR.Policy.UpdateReference →
      Option CPR.Position → List CPR.Policy.TimedReport →
      CPR.Policy.StreamState × List (Option CPR.Position)) : Prop :=
  ∀ geo update reference reports,
    implementation geo update reference reports =
      CPR.Policy.decodePositions geo update reference reports
```

The geographic/numerical boundary and reference callback are explicit parameters. The actual adapter in CPRFloat supplies same-order binary64 local/global decoding and haversine; those numeric computations are tested, not proved accurate by this refinement. Initial reference and timestamps use finite represented values; arbitrary malformed byte inputs are covered by the byte decoder before entering this interface. `CPR.Policy.stream_nonvacuous` proves a nonempty surface stream resolving at an actual reference/airport. ## CPROutOfOrder

An airborne report older than its opposite-parity cache returns unresolved with both state and receiver reference unchanged. This rules out accidental state mutation or stale pairing on the early-return path.

```lean
def CPROutOfOrder : Prop :=
  ∀ geo update (state : CPR.Policy.AircraftState) reference timestamp
      (code : CPR.Encoded) altitude metadata,
    Binary64.sub timestamp
      (if code.odd then state.evenTimestamp else state.oddTimestamp) < 0 →
    CPR.Policy.stepAirborne geo update state reference timestamp code altitude metadata =
      ⟨state, reference, none, true⟩
```

The premise is the actual rounded timestamp subtraction being negative; it is not a condition on ideal real-valued time. There is no source-wide chronological input assumption. `CPR.Policy.out_of_order_nonvacuous` proves a report at 0 seconds against a cache initialized at 1 second, for every geography and callback. This condition applies to airborne reports; the pinned surface branch has no corresponding out-of-order filter.

## Reference semantics and deliberate limits

The pure CPR equations use exact rational arithmetic. The tracking state machine in `Spec/CPRPolicy.lean` specifies rs1090-derived pairing, time windows, reference selection, motion checks and airport policy; its coordinate and geographic distance results are an explicit tested Float boundary; `CPRFloat.numericalGeography` supplies the complete numerical adapter, preserving intermediate rounding before policy comparisons. The encoder-side quantized-zone predicate in GlobalAdmissible and the separate reconstructed-zone rejection predicate are properties of the mathematical encoding, not claims that arbitrary moving reports or an arbitrary reference can be resolved. Timestamp/geodesy values supplied by callers must be represented with their actual numeric behavior; NaN distances have explicit comparison semantics. No global surface decoder is included; it is a possible extension after GOAL section 8.

The source-defined exact values precede the Float presentation expressions in `Spec/Presentation.lean`. f32/f64 rounding, libm `hypot`/`atan2`, and geodesy are tested rather than proved, as authorized by GOAL. This does not exempt Float-dependent inference branches: those have the explicit Binary64 rational semantics and finite-range obligation above. The exact canonical JSON emitter and external differential runtime are section 4 deliverables, not completed checkpoint proofs. JSON key spelling, omission and Float evaluation remain tested adapters consuming the proved semantic record; the current capstones do not claim a proof of a not-yet-written serializer.

**rs1090-derived definitions:** Comm-B inference and fitted scores; BDS18/19 bitmap ordering and BDS21 registration layout; TC28/29 detail and TC31 capability/operational subfields; unavailable/sentinel conventions; receiver plausibility rejection; callsign removal of all spaces; rounded selected altitudes and numeric operation order; AC13 reserved metric compatibility conversion; API prefix and parity acceptance policy; CPR pairing/reference/motion/airport policies and reporting labels. See SCOPE.md and docs/COMMB.md for the field-by-field list and docs/PAYLOADS.md for source status. Direct codecs combine source tables with these explicitly identified receiver predicates. No claim that these oracle choices are mathematical consequences of ICAO is intended.

Known source disagreements have separate standard and oracle projections: standard Comm-D has a two-bit descriptor; standard NL(±87)=2; standard TC19 subtype 2 scales by 4 and treats zero component codes as unavailable; standard GNSS source/delta and TC20–22 altitude semantics are retained; `cbStandardThreat` preserves BDS30 range saturation, bearing sectors/reserved codes and Mode C altitude from Annex 10 IV§4.3.8.4.2.2.1.5–6 alongside its separately named oracle view. `DISCREPANCIES.md` contains concrete observations and source clauses. An rs1090 bug is not a reason to weaken the standard theorem, and pending discrepancies are not blanket differential exemptions. The 50000 ft receiver filter remains a compatibility acceptance policy while altitude-code theorems retain the full representable range.

The BDS50 all-input refinement is proved and its component benchmark/differential checks are complete. No whole-decoder refinement, complete standard theorem, 10M-message conformance result or performance target is claimed at this amendment review. `scripts/check_draft.sh` validates the amended review artifacts, source anchors, dependency audits and proved BDS50 pilot; `scripts/check_all.sh` deliberately fails until the approved lock and full section 4 gate exist. No commit is made on the strength of the draft check.
