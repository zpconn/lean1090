# Generation 4: payload fields from machine shifts and masks

The complete [gen3 diagnostic](GEN3-COST-BREAKDOWN.md) identifies Comm-B inference as the largest stage: 20,413,385,286 of 52,042,380,076 instructions (39.22%). Within it, `payloadBits` has 3,121,720 calls and 6,396,909,632 inclusive instructions. Its generated C performs two generic natural-number exponentiations plus division and remainder per extraction. These overlapping instruction costs are diagnostics, not a predicted speedup. Independent review passed before this change began.

`Impl.payloadBits` now uses a UInt64 shift and mask when width is below 64. The offset remains exactly `56 - (start - 1 + width)`, including natural-number subtraction at zero. For every natural start and width below 64, the offset is below 64 and offset plus width is at most 64. Therefore truncating an arbitrarily wide word to its low 64 bits preserves the requested field. Widths at least 64 retain the original unbounded division/remainder formula.

The machine mask has exactly the natural value `2^width - 1`; its proof uses Lean core lemmas only. The universal `payloadBits_lt` theorem supplies erased bounds at all three runtime array/Fin sites in Comm-B. Those edits do not add runtime checks. `Proofs.PayloadBits.payloadBits_eq` proves equality with the frozen formula for every natural word, start and width, without a layout-validity or word-bound hypothesis. Kernel witnesses cover zero width, width 63, width 64, over-wide words and a field ending at bit 64. No frozen file, trusted primitive, table or cross-message state is added.

The first helper build passed (five jobs). The first integrated build failed because the old Comm-B density-length proof used definitional equality between runtime and reference functions. Replacing that unfrozen shortcut with a structural proof of the same at-most-four bound resolves it. The second integrated build passed (3,509 jobs), including the unchanged decoder refinements and only permitted axioms. Both build logs are retained in [tests/evidence/optimization/gen4/integration/](../tests/evidence/optimization/gen4/integration/).

The native-code review passed all 16 structural/source checks. The live fast branch contains native shifts, masking and natural-number tagging; the two natural powers and division/remainder remain only in the width-at-least-64 fallback. The helper is inlined and the proof names are erased. Comm-B's C text changes by checked local renaming and independent assignment reordering, while its entire native object is byte-identical to gen3. See [the native review](../tests/evidence/optimization/gen4/native-review/README.md).
