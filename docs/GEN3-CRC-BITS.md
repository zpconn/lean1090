# Generation 3: extract CRC bits from two machine words

The complete [gen2 diagnostic](GEN2-COST-BREAKDOWN.md) identifies frame/CRC as the largest exclusive stage: 34,541,501,451 of 73,545,228,488 collected instructions (46.97%). Within that stage, 26,320,784 calls to `Nat.testBit` account for 21,957,771,021 inclusive instructions. These overlapping instruction counts are diagnostic evidence, not a benchmark result or predicted speedup. Independent review passed before this change began.

`Impl.Parity.syndrome` now extracts the low and next 64 bits once per call. Its existing fold reads those two `UInt64` values for indices below 128, using shift/mask operations. For indices at least 128 it still reads the full natural number with `Nat.testBit`. The CRC step, fold order and result type are unchanged. There is no state across calls, no table and no corpus-dependent key.

`wordBit_eq` establishes the machine-word bit operation for indices below 64. `cachedBit_eq` establishes the combined operation for every natural word and index, including arbitrary words wider than 128 bits. Substitution in the original fold preserves `syndrome` for every width and word, and feeds the unchanged all-input decoder refinement. The two machine branches explicitly prevent masked shift counts from wrapping. Kernel witnesses cover the 64 and 128 boundaries.
