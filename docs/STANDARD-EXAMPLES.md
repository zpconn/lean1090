# Published decoding examples

`Spec/StandardExamples.lean` checks every complete worked Mode S frame found in the consulted second edition of Junzi Sun's *The 1090 Megahertz Riddle* (2021, revised PDF), plus the raw-only frames in its Quick Start transcript. It contains 29 successful literal-byte frame anchors, one corrupt-frame rejection, and source-specific semantic and arithmetic checks. That module has 65 named kernel-checked theorems and 57 `example` declarations. `Spec/StandardFullExamples.lean` adds 30 complete-result equalities and 30 corresponding `example` declarations, for 95 named proofs and 87 examples across the two modules. Repeated appearances of the same frame reuse the same anchor; they are not counted as distinct inputs.

The book does not supply a complete `Spec.Message`/`Report` value. Each frame anchor therefore states `(Spec.decode literalBytes).map Message.fields = some literalFrame`. Additional assertions project the quantities actually published by the source from the returned semantic record and compare them with fixed constants. In those independent source assertions, no expected frame or published value is made by calling an encoder, decoder, `report`, or inference function. The helper projections only look up values already in the returned message. Every raw frame's complete wire fields, including parity and spare bits, are fixed independently as literals. The corrupt-frame assertion directly requires `Spec.decode literalBytes = none`.

This distinction avoids attributing unreported fields to a book or letting the decoder construct its own expected answer. In the one hypothetical BDS50 interpretation of a rejected candidate, the source asks what the fields *would* mean under that assumption: a separate theorem applies the BDS50 field formulas to the MB block returned by `Spec.decode`, while another checks that BDS50 is absent from the actual candidate list.

Source acquisition, editions, URLs, and PDF SHA-256 values are recorded in [SOURCES.md](SOURCES.md). The inventory was made from all 160 pages of the cached Sun PDF and its extracted text. Figures 10.2, 17.1–17.3, and 18.1–18.2 were also rendered and visually read; notably, the BDS45 message exists only as outlined glyphs in figure18.2 and is absent from ordinary text extraction. PyMuPDF1.28.2 was installed in the project-local virtual environment for that inspection. No rs1090 code was used to derive the expected source values.

## Complete decoded-result fixtures

`Spec/StandardFullExamples.lean` additionally gives the requested complete form for every full frame:

```lean
example : Lean1090.Spec.decode identificationBytes = identificationExpected := identification_full
```

Each `...Expected` constant is a complete literal `Option Message`, including every field of `Report`, both standard and oracle semantic records, and the entire numeric expression trees. None of these expected terms invokes `decode`, `encode`, `report`, any inference routine, or another semantic projection. The corrupt frame has the direct complete result `none`.

The full values were captured once from an evaluation of the present reference decoder, rendered as literal Lean terms, and then independently checked against kernel evaluation. They are **regression fixtures**, not a claim that every additional report field was published by Sun. Capturing an answer from the decoder cannot establish that its table interpretation was correct; the separate manually source-anchored assertions in `StandardExamples` perform that role. The extra equalities retain all project-specific fields and supply a concrete complete output for review without inventing provenance. They are fixed source files, not regenerated by the gate, so subsequent changes must continue to match both the complete fixtures and the independent source claims.

The source's global-surface algorithm remains outside the approved scope. Its complete input frames and CPR fields are checked, and its published final odd position is independently checked using the in-scope local surface decoder with the same supplied reference. This is not a claim to have implemented or proved global surface pairing.

Similarly, chapter19's final ADS-B-assisted BDS disambiguation and Mach-to-CAS conversion are outside `Message::from_bytes` and the approved per-message inference scope. The example's payload values and initial ambiguity are checked; no additional stateful classifier is silently added.

The decoder's model deliberately ends at exact numbers and explicit floating expression trees. The 159.20kt and 436.1kt displays additionally have kernel-checked rational square bounds. Printed atan2 headings182.88°/271.4° and the platform Float evaluation remain in the established tested presentation boundary; no theorem about Lean's opaque Float or a platform atan2 is claimed. The source's exact components and the ground-velocity operation tree are kernel checked, so these examples still anchor the proof-visible input to that adapter. Display rounding of rational fields is represented by the exact pre-rounding value (for example243.984375° rather than243.98°).

## Source contradictions retained explicitly

These are discrepancies inside the teaching source, not reasons to weaken checks or change the standard's field definitions.

1. **Figure10.2, p.91.** The figure gives data`101101111000`, divisor`1101`, quotient`110010110`, and remainder`010`. Exact carryless multiplication shows the actual remainder for those data/divisor/quotient is`110`. `toy_crc_source_disagreement` proves the identity with110 and disproves it with the printed010. The published ModeS CRC-24 examples all pass unchanged.
2. **§6.4.1, p.65.** One sentence calls the latest message “even”, while the supplied ordering and equations correctly select the odd message. The example uses the explicitly marked latest odd frame and its printed equations.
3. **§6.4.2, p.67.** The prose/equations give the new position52.3205605…,4.7357352…. The following Python output repeats the earlier position52.32061,4.73473. The theorem checks the new literal frame against equations6.17/6.20; the stale Python output is not asserted as true.
4. **§7.3, p.74.** Equations7.13/7.14 correctly give−8 and−159. Equations7.15/7.16 print−9 and−160 even though the final159.20kt/182.88° numbers correspond to−8/−159. The literal component assertions and rational speed bound select the consistent field formula and result. The MessageB decomposition on p.70 also prints TC5 in its decimal row despite the hex/binary header and chapter definition giving TC19; the fixture asserts19.
5. **§16.2, p.120.** The prose support list omitsBDS52, but the set-bit list includes bit18 and the Python result includesBDS52. The fixed bitmap assertion checks all11 set bits against table16.2.
6. **§18.1, p.137.** The Python temperature function prints both−48.75 and−24.375 for competing scale interpretations. The source's chosen table18.1 and figure18.1 use0.25°C; that approved version choice produces−48.75°C and is the one checked.
7. **§19.3/fig19.2, p.144.** Compass angles are displayed coarsely as250°/359°. The exact signed field values are checked rather than treating those coarse labels as exact degree values; normalized values are250.48828125° and359.82421875°.

## Reproducible verification

Executed successfully:

```sh
lake build Spec.StandardExamples Spec.StandardFullExamples
```

All proofs use `decide +kernel` (anonymous examples refer to the named checked theorems). The regular gate must import this module so a standard-table change that breaks a published example fails the build. Generated audits containing `#print axioms Lean1090.Spec.StandardExamples.<name>` for all 65 source-anchor theorems and `#print axioms Lean1090.Spec.StandardFullExamples.<name>` for all 30 complete-result theorems check the actual proof constants, rather than merely printing axioms of proposition definitions. Both audits passed with only the three permitted standard axioms (or fewer).
